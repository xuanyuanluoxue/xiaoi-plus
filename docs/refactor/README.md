# 核心重构：目标与边界

> 状态：**WP1~WP5 已完成并合并；下一步 WP6（状态模型/UI）**
> 目标版本：`0.12.0`（先发 `0.12.0-beta.1`）
> 基线版本：`0.11.0-beta.4`（versionCode 15）
> 文档建立：2026-11-06

## 1. 为什么重构

2026-11-05 的产品/工程审计确认：当前问题不是单点 bug，而是三个根因：

1. **桥的信任模型不成立**：loopback 被当成可信；端口发现先把 Bearer Token
   发给 8771~8775 的每个端口；`/health` 文本可被本机任意应用伪造。
2. **配置没有单一事实源**：`config.json`、模块 prefs、小爱 target prefs 三份状态
   互相覆盖；target prefs 读取端还把 `bridge`/`marker` 硬编码为 `true`。
3. **状态没有模型**：已启用 / 可用 / 已确认 / 已推送 / 未同步混用，
   App 侧校验可以伪造“已确认”；用户无法判断“现在到底生效没”。

因此本重构的目标不是“把界面再改一遍”，而是重做 **桥、配置、状态** 三个核心子系统。

## 2. 范围

### 做（B 方案：核心重构）

- Bridge 生命周期、传输与鉴权
- 配置单一事实源、revision、迁移与损坏恢复
- 首次配置 bootstrap
- 状态模型与主页/配置页/日志页的状态表达
- 必要的 `ConfigActivity` 拆分与测试补齐
- 发布门禁加固

### 不做（本次不碰）

- 不重写 Hook 目标与已验证的小爱适配逻辑
- 不更换包名、签名密钥、`plus.xiaoi.module` 身份
- 不引入 Kotlin、Gradle、第三方运行时依赖
- 不改写 MCP 工具语义（除鉴权/传输层）
- 不做与 0.12.0 无关的新功能（语音动作引擎、统计增强等）

## 3. 优先级

1. **安全**：本机恶意应用与局域网对端都不能拿到 Token/API Key。
2. **可信状态**：用户能回答“配置有没有保存 / 有没有推送 / 小爱是不是在用”。
3. **可用性**：首次配置能闭环；关闭就是关闭；错误可行动。
4. **可维护性**：核心状态机可测；页面可拆；发布门禁可执行。

## 4. 威胁模型

**防御对象**

- 手机上的其他普通应用（不需要 root）
- 同一局域网内的其他设备（不可信 Wi-Fi）
- 误操作/配置损坏，不防物理接触与 root

**必须保证**

- 不向未证明身份的端口发送 Token
- 未开启 MCP 时，MCP/CLI/日志/统计能力不可达
- Token 为空时不存在“任意本机应用可写配置”的窗口
- LAN 模式必须显式开启 + Token 非空；`/config`、`/island` 裸端点永远只限本机
- 日志、导出、错误信息不泄露 apiKey/token
- 配置损坏不静默覆盖唯一事实源

## 5. 兼容性

- 包名 `plus.xiaoi.module` 不变
- 签名密钥不变，支持从 beta.4 覆盖安装
- 现有 `config.json` 必须可迁移；迁移失败保留原文件并提示
- 小爱 `8.2.65.4714` 白名单行为不变；版本不匹配仍 no-op
- 现有 MCP 客户端协议（JSON-RPC 2.0 / `2025-03-26`）不变
- 旧 token 在迁移后仍可用，直到用户主动轮换

## 6. 成功标准

重构完成的判据（全部满足才算完成）：

1. 代码中不存在“向未认领端口发送 Bearer Token”的路径
2. 关闭 MCP 后，数据面端口/能力不再可达；重启小爱后状态仍保持关闭
3. 首次配置不需要无鉴权 `/config` 窗口，或该窗口有一次性、可验证的授权
4. `config.json` 是唯一事实源；三份状态有明确 revision/同步状态
5. 主页只有“小爱运行时”能显示“已确认”；端点校验单独命名
6. 暂停状态允许编辑服务商/模型/密钥
7. 日志/诊断不再被 MCP 开关绑架（或明确提示并一键开启）
8. 从 beta.4 升级不丢配置、不丢 Token、不需要卸载重装
9. 新增的纯 JVM 状态机/鉴权/HMAC 测试全绿；真机回归覆盖 P0 场景
10. CI 强制跑一致性检查；tag 构建没有正式签名密钥时不允许创建 Release

## 9. 执行方式

1. 计划已冻结；WP1~WP5 已完成并合并；后面的包一个工作包一个开发 Agent
2. 每个包合并前跑 `tests/run.sh` + `build.sh` + `check-consistency.sh`
3. WP1/WP3/WP4 安全相关包合并前再过一次独立安全复核
4. 每个包独立 commit；不跨包改文件
5. 全部完成后跑真机 P0 矩阵，发 `0.12.0-beta.1`

**在首个开发 Agent 启动前，不再修改 `app/`、`tests/`、`build.sh`、`.github/`。**
