# 安全、隐私与回滚

本文说明：密钥存在哪、数据发到哪、桥开了什么端口、出问题怎么退回去。
**一句话：模块不联网上报，密钥只在本机；风险主要来自「改客户端请求」这件事本身。**

## 1. 密钥存在哪里

| 项 | 实际情况 |
|---|---|
| 存储位置 | 模块自己的私有目录 `/data/data/plus.xiaoi.module/shared_prefs/xiaoi_plus.xml` |
| 存储形式 | 明文 XML（Android 不会为普通应用额外加密；设备加密只保护关机状态） |
| 谁能读 | 模块自己、root、ADB（`run-as` 需 debuggable 版）、系统 |
| 谁能写 | 只有模块自己（`MODE_PRIVATE`） |
| 小爱进程怎么拿到 | LSPosed 的 `XSharedPreferences` **只读**读取，复制成内存快照，不写入小爱目录 |
| 桥的 token | 同样存在这份 XML 里，用于本机/局域网 HTTP 鉴权，不参与模型请求 |
| 有没有进日志 | 没有。日志只输出 `model=` 名称和 hook 成败 |

补充（0.12.0 起）：配置事实源改为 App 私有目录
`/data/data/plus.xiaoi.module/files/config.json`（schema v3，带 `rev`），不再写
`Android/data`；其他应用、`adb shell` 普通用户和 `run-as` 之外的工具都读不到这个文件。
App 内改动 1~2 秒自动应用；旧 `Android/data/plus.xiaoi.module/files/config.json`
会在首次打开新版 App 时一次性迁移（成功后删除旧文件，已有私有配置时归档为
`config.json.legacy.<ts>`）。该文件含明文 apiKey——设备借人/送修前请先清空密钥或卸载模块；
需要备份请用 App 内的「完整备份」，不要把含密钥的导出文件留在公共位置。
运行时变更（MCP `switch_model`）只写小爱 prefs，不回写该文件。

实践建议：

- 单独申请一把**低额度**的 key，不要用主账号或和支付/云资源绑定的 key
- 泄露后立刻在服务商后台吊销，改 key 只需在设置页重填并重启小爱
- 设备借人 / 送修前，先在模块设置页清空 key，或直接卸载模块（卸载会连同私有目录一起删除）

## 2. 数据去了哪里

- 对话请求只发往你在设置页填的 `baseUrl`，和直接用该服务商的 API 一样，
  **服务商能看到完整对话内容**——这是 BYOK 的固有代价。
- 模块**没有**统计、埋点、远程配置、自动更新、崩溃上报。
- 设置页本身不发任何网络请求。
- 模块 APK 声明了 `INTERNET` 权限；实际请求由小爱进程（本身已有网络权限）发出。
- 模块不读取、不上传你的通讯录、短信、位置或小爱历史记录。

## 3. 本地能力桥（实验性，默认关闭）

设计目标：让本机或**可信局域网**里的脚本调用小爱，而不是把能力暴露到公网。

- **默认只绑 loopback**：监听 `127.0.0.1:8771~8775`，局域网和公网都连不上。
- **局域网模式（0.12.0 起更强）**：设置页打开「允许局域网访问」且 Token 是
  **32 位十六进制（128 bit）**时，才监听 `0.0.0.0:8771~8775`，同一 Wi-Fi 的电脑可直连。
  短 token / 非 hex token 不阻断本机 MCP，但只绑 loopback（不会把弱 token 暴露到局域网）。
- **Bearer token 鉴权**：每个请求必须带 `Authorization: Bearer <token>`，token 在设置页填写；
  **留空 = 拒绝所有请求（401）**。`/health` 也只接受 Bearer。
  **例外**是用户显式打开的「免鉴权」与「弱密码」（见 §3.1），默认都关闭。
- **免鉴权 / 弱密码（可选，默认关闭）**：设置页「接入 › 令牌与局域网」。
  「允许免令牌调用」打开后本机与局域网都不校验 Bearer；「允许弱密码用于局域网」
  允许任意非空密码作为 token（默认要求 32 位十六进制）。两者都要显式保存，见 §3.1。
  代价：手机上的**任何应用**都能无令牌调用 8771 的全部能力（读配置/日志、切模型、
  驱动小爱）；因此默认关闭、打开需二次确认、可随时关闭（保存后 1~2 秒生效）。
  验证方式：`curl http://127.0.0.1:8771/health` 无 header 返回 200 即已生效；
  从电脑经局域网访问仍应返回 401。
- **配置只能由 App 写**：`POST /config` 自 0.12.0 起固定返回 `410 Gone`，不解析 body、
  不写 prefs；`/island` 仍只接受 loopback。MCP 的 `xiaoai_switch_model` 只允许
  `model`/`marker`，远程传入 `baseUrl`/`apiKey`/`bridge`/`lan` 会得到 `isError=true`，
  不能把 apiKey 导向攻击者端点，也不能远程打开数据面。
- **限流与有界读取**：`/health`、`/island` 按来源 IP 30 次/10s（超限 429）；
  单行 header 上限 8192 字符、header 最多 128 行；请求线程池 core=4/max=8/queue=32，
  队列满直接 503，不阻塞 accept。
- **日志边界**：运行日志只含 hook 成败、模型名、端口与调用摘要，**不含 apiKey / token / 对话正文**；每行带 `tag/ts/pid` 便于定位进程与跨天排序。内存保留 300 条，并滚动落盘到小爱私有目录 `files/xiaoi_plus.log`（256KB，保留 `.1`），卸载即随应用数据删除。
- **端点很少**：`GET /health`（自检）、`GET /logs`（日志）、`GET /cli`（转发一条 CLI 命令）、`POST /mcp`（标准 MCP，JSON-RPC）、`POST /island`（触发一次岛提示，仅本机）。`POST /config` 已停用（410）。`/mcp` 与 `/cli` 等价，是同一 token 下的同一能力，不额外扩大权限面。
- **默认关闭**：设置页「MCP 接口」与「允许局域网访问」默认都不勾选。
- **失败即停**：桥启动失败只写日志，不影响模型重定向与标记。
- 关闭开关 → 保存 → 立即重绑；重启小爱后端口不再监听。

**注意**：loopback 对手机上的**所有应用**可见；局域网模式下同一 Wi-Fi 的**所有设备**都能尝试连接。
Token 是唯一的门禁（除非你主动打开免鉴权 / 弱密码），请用设置页「生成」产出的 128 位随机串，不要复用别的服务密码。
局域网模式要求 32 位十六进制 token；短 token 只允许本机访问。
公共 Wi-Fi、公司网络、宿舍共享网络建议保持局域网关闭，改用 adb 隧道。
发现异常时用 `adb shell ss -ltn | grep 8771~8775` 确认监听地址与进程。

```bash
# 手机上自检（Termux 或 adb shell）
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8771~8775/health
# ok facade=true
```

### 3.1 可选：免鉴权 / 弱密码（默认都关闭）

| 开关 | 行为 |
|---|---|
| **允许免令牌调用** | 本机与**局域网**都不校验 Bearer；打开需二次确认 |
| **允许弱密码用于局域网** | 任意非空密码都能作为 Bearer；默认要求 32 hex |
| 生效内容 | 8771 的 `/health`、`/mcp`、`/logs`、`/stats`、`/cli`，以及经它转发到 App 进程的全部设备动作（0.16.0 起只有这一个端口） |
| 关闭后 | 保存后 1~2 秒内恢复 401，不需要重启小爱 |
| 代价 | 同一 Wi-Fi 下的任何设备都能驱动小爱 / 执行设备动作 / 读日志与配置摘要 |

实现要点：

- `BridgePolicy.allowsAnonymous(noAuth)`：唯一的免鉴权判据（不再区分来源）。
- `BridgePolicy.bindHost(lan, mcp, token, noAuth, weakToken)`：
  `noAuth` → 可绑 `0.0.0.0`；`weakToken` + 非空密码 → 也可绑；
  否则仍要求 32 hex。
- 设备动作没有独立端口：App 进程不再监听，全部经 8771 的 `/mcp` 转发。
- 配置字段：`mcp.noAuth` / `mcp.weakToken`，缺省都 false，旧配置自动兼容。

> 这两个开关是**测试便利选项**：只在个人设备 + 可信网络（或云端无人值守的测试机）上开，
> 用完立刻关。局域网打开免鉴权时，任何接入同一 Wi-Fi 的设备都能读配置摘要
> （`xiaoai_config` 不含密钥明文），并驱动小爱执行任务。

#### 3.1.1 CORS 与「浏览器也能调」的风险（0.16.0）

唯一的 MCP 端点（8771）回 `Access-Control-Allow-Origin: *`，并支持 `OPTIONS` 预检 ——
这是为了让浏览器里的面板/网页 Agent 能直接调用。代价必须写清楚：

- **只影响浏览器**：跨域放开不等于绕过鉴权，默认仍然需要 `Bearer` token。
- **`noAuth` + 浏览器 = 真实风险**：开了免鉴权时，用户访问的任意网页都能向
  `http://<手机IP>:8771/mcp` 发 `tools/call`，包括
  `xiaoai_action`（执行设备动作）。**局域网 + 免鉴权 + 浏览器**三者同时成立时，
  建议只在隔离的测试网络上使用，用完立刻关闭。
- **弱密码同样可被网页试出来**：`test1234` 这类密码在局域网广播下没有实际保护力，
  仅为联调方便，不要与「允许局域网访问」在不受信任的网络里同时开启。
- 不需要浏览器接入时，可直接关闭「允许局域网访问」，CORS 头本身不会带来本机风险。

## 4. 回滚

按影响从小到大，任选其一：

**A. 只关功能（保留模块）**

1. 打开「小爱同学+」设置页
2. 取消勾选「回复开头显示 `[model=...]`」
3. 清空「模型名」（清空后模块直接跳过，等于关闭）
4. 强制停止小爱再打开

```bash
adb shell am force-stop com.miui.voiceassist
```

**B. 停用注入（保留 APK）**

1. LSPosed 管理器 → 模块 → 关闭「启用模块」
2. 或保留模块、把作用域里的「超级小爱」取消勾选
3. 重启小爱（必要时重启手机）

**C. 完全移除**

```bash
adb uninstall plus.xiaoi.module
```

或在系统里正常卸载。卸载后私有目录（含 key）一并删除。
模块**从不修改小爱的 APK、数据和系统分区**，所以卸载即恢复原样。

**D. 已经进不去系统 / 小爱反复崩溃**

- 模块只 hook `com.miui.voiceassist`，**不会导致开机循环**；最坏情况是小爱自己崩溃
- 用 LSPosed 管理器的「安全模式」，或长按音量键进安全模式后停用模块
- 实在不行：`adb shell pm disable-user com.miui.voiceassist` 先让小爱不启动，再处理模块

## 5. 风险提示（请读完再用）

- **账号风控**：改写请求端点/参数属于修改客户端行为，可能触发服务商的设备与协议校验，
  极端情况下影响小米账号或小爱服务的使用。风险自担。
- **OTA**：模块不动系统分区，本身不影响 OTA；但 root / LSPosed / 其他系统级修改
  可能导致 OTA 校验失败或升级后模块失效（白名单外自动 no-op）。
- **升级即失效**：小爱每次更新都可能改混淆名。未适配版本会直接跳过，
  **不会**把请求发到错误的地方，也不会 crash 主流程。
- **bootloop**：本项目所有 hook 都包了 try/catch，异常只写日志；
  已知的崩溃面仅限于小爱进程自身。
- **服务条款 / 著作权**：仅供学习研究。不要二次分发、售卖，不要用来绕过付费能力。
- **没有 warranty**：出任何问题（封号、数据、设备）由使用者承担。

## 6. 给贡献者的安全约束

提交 PR 时请保持：

1. 不新增任何网络上报、统计、远程开关
2. 不把 key 写进日志、异常信息、Toast
3. 桥默认只能绑 `127.0.0.1`；局域网模式必须显式开关 + 32 hex token
   （或显式打开弱密码 / 免鉴权），
   且 `/island` 永远只接受 loopback，`/config` 固定 410
4. 新增 hook 必须 try/catch，异常不得抛回小爱
5. 不改 `AndroidManifest.xml` 的权限，除非在 PR 里说明理由
